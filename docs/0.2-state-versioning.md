# Subtask 0.2 — Версионирование состояния и compat слоя

## Контекст
Состояние хранится через eframe `persistence` (`APP_KEY`). Добавление полей уже сталкивается с риском ломки старых сохранений. Нужна явная миграция.

## Цель
- Добавить поле `schema_version` в корне app state (или рядом) с разумным дефолтом для старых сохранений.
- Добавить миграционный шаг: при загрузке с `schema_version < N` проходить через `migrate(...)`.
- Обновить все места, где инициализируется `TemplateApp::default()`.

## Ограничения
- Старые сейвы должны загружаться без падения (defaults + миграция).
- TDD: тесты для старых форматов сейва.

## Критерии приёмки
- Тест: загрузка сейва без `schema_version` → корректное состояние + счётчик миграции/тестная проверка.
- `./check.sh` проходит.

## Заметка для будущих миграций
`schema_version` живёт в `src/app.rs` (`CURRENT_SCHEMA_VERSION`). Добавление полей в app state: увеличить `CURRENT_SCHEMA_VERSION` и добавить шаг в приватный `fn TemplateApp::migrate()` — шаги выполняются при загрузке в `TemplateApp::new`. Поле должно иметь serde default (старые сейвы грузятся, затем мигрируются). Тесты миграций — в модуле `app::tests`.
